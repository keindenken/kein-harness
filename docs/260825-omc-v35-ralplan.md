### 2.5 The readout family is THREE, not two, and §5.5's recommendation is false (READ + RUN-P)

**Three readouts.** §5.7 describes the family as the refusal marker and the instance hint. Source has a third — `packages/descvi/src/react/overlay/canvas/use-resize-handles.ts#export const SHIFT_REFUSAL_HINT_ID = "dsh-ring-refusal-hint";`, the transient aspect-lock refusal S42-4 added *after* §5.7 was written at `b70eff6`. All three go through `styleReadout` and then override colour and border; the third's override is `packages/descvi/src/react/overlay/canvas/use-resize-handles.ts#lockHint.style.color = isDark ? "#FCD34D" : "#B45309";`. **§5.7's measured contrast table covers two of the three**, so the follow-up it routes was sized against an incomplete family.

**RUN-P, instrument validated:** an sRGB contrast probe reproduces §5.7's published marker and hint figures and §5.5's six group figures exactly, in both themes, before being pointed at anything new. On that instrument the third readout measures **5.02 light / 12.83 dark** — it clears AA and is not the problem. ⚠ **Every DARK figure in this family carries an unstated backdrop and this plan states it: the readout fills are `rgba(15,20,26,0.92)` and `rgba(255,255,255,0.94)`, so a dark ratio depends on what is behind them.** The published figures assume the dark chrome (`#0F141A`) behind the fill; over pure black the same three measure 9.89 / 7.32 / 13.02 against 9.75 / 7.21 / 12.83. The light figures have no such dependence and reproduce exactly. §5.7's own weakest member, the instance hint, remains the weakest; this plan does not restate its figures, which have their home in §5.7.

**§5.5's chip-tint recommendation does not do what it says.** Compositing the group's `light` shade over the white chip fill at α 0.08 → 0.24 **lowers** the glyph-on-fill ratio monotonically for every group, because a white fill is already the maximum-contrast background for a dark foreground. ⚠ **TWO SUCCESSIVE DRAFTS OF THIS PARAGRAPH PUT A FALSE REASON UNDER A TRUE CONCLUSION, AND THAT IS THIS PLAN'S MOST PERSISTENT FAILURE SHAPE — the reason is what §3.4 schedules into the co-owned spec.** For the record, both errors: the first said teal and orange fall furthest (blue does); the second published **−0.65 / −0.37 / −0.42 as the drop "across α 0.08 → 0.24"** when those are the **α 0 → 0.24** drops — the 0.08 → 0.24 drops are −0.41 / −0.24 / −0.27 — and claimed teal and orange **cross** the 3:1 floor within that range. **Neither crosses**: they end at 3.37 and 3.14, both above 3.0. Re-measured on an instrument that reproduces §5.5's six published figures exactly, the crossings are at α ≈ 0.33 (orange), ≈ 0.53 (teal) and ≈ 0.92 (blue), all outside any alpha the recommendation contemplates.

**The conclusion never needed either reason. DR46-5 closes on MONOTONICITY ALONE**: a white fill is already the maximum-contrast background for a dark foreground, so any tint lowers every ratio, and a recommendation whose stated purpose is to LIFT two groups cannot be implemented by an operation that lowers all three. ### 3.1 C46-1 — the DECLARED-KIND amendment to C9 / G42-7 (RULED — DR46-1)

**Every operable node under `#dsh-ring-layer` declares which affordance it offers, and the gate checks the declaration's own obligation.**

1. `data-v3-glyph-control` keeps its meaning and its completeness half **unchanged**: an operable node carrying no marker is still named, and that is still the half that catches the hazard C9 exists for.
2. The marker gains a VALUE naming the affordance kind. **THREE kinds**, and no fourth without amending this contract:
   - **`glyph`** — an `svg`/`[data-glyph]` descendant that is rendered. Today's rule for every panel control.
   - **`glyph-conditional`** — a mark that is present in the DOM and **hidden as a measured function of the node's own size**. ⚠ **This kind exists because an earlier revision of this clause turned shipped, spec-ratified, separately-gated behaviour into a violation.** `packages/descvi/src/react/overlay/canvas/use-spacing-affordances.ts#glyph.style.display = Math.min(rect.width, rect.height) >= SPACING_GLYPH_PX ? "block" : "none";` hides a spacing mark below the size at which it would paint noise; the visual spec ratifies that as a third state; and `e2e/spacing-gesture.spec.ts` **asserts both halves of it**. A contract that made every 4–7 px spacing strip a violation in exactly the state another gate mandates was wrong, not strict. **The obligation is that the mark is present and its hiding is a function of the node's own measured size.**

     ⚠ **PRICED AS A NARROWING, NOT AS A DISSOLVED MUTANT — and an earlier revision of this clause overclaimed exactly the way r3-C1 forced the cursor leg to stop overclaiming.** It said the kind *dissolves* the mutant DR46-1's rejection of option (e) calls unbuildable. **It does not.** Clause 2 as written has no floor, no ceiling and no requirement that the threshold be reachable, so a later phase can write `display = size >= 9999 ? "block" : "none"`, declare the kind, and satisfy every word — option (e) with three characters of attribute value. And the two-state obligation is stated per NODE while the only gate that discharges it (`e2e/spacing-gesture.spec.ts`) collects its two states from **different fixtures** and closes on inhabitance, never from one node crossing its own threshold.

     **What the kind actually buys is narrower and still worth having:** it stops a permanently-hidden mark from being *silently* legitimate. The hider must name itself, and a reviewer reading a `glyph-conditional` declaration knows to ask what the threshold is. **That is a labelling requirement, not an enforcement one**, and §9's residual-risk entry says so rather than letting the stronger reading stand.
   - **`cursor`** — a ruled pointer cursor over a non-zero hit box, per clause 4.
3. **`cursor` is admissible only for a node satisfying ALL of a four-term conjunction**: it carries `data-dsh-handle`, **and** it is contained in `#dsh-handle-layer`, **and** it carries a cursor from the ruled table, **and** it has no focusable descendant. ⚠ **The container term is a NARROWING TERM, not the universe** — the scanned universe stays layer-wide, which is why this does not reopen DR46-1(b). The container term is required because `data-dsh-handle` alone is the selection shield's concession marker, shared with the spacing family and with a popup that contains a text input (§2.13); a class-based grant would be exactly the licence P46-1 forbids.
4. **The `cursor` obligation is POSITIVE and must be able to fail on a same-commit mutation.** The node's cursor must be the entry `packages/descvi/src/react/overlay/canvas/handle-glyphs.ts#export const HANDLE_CURSOR: Record<HandleCompass, string> = {` publishes **for that node's own `data-dsh-handle` value**, over a non-zero hit box. Membership alone is not enough: a table the same commit could extend with `default` is a substitute obligation satisfiable by weakening the table, which is why G46-4's mutant is in the LOOKUP KEY.

**Why the value and not a second attribute.** A second attribute is a second thing to forget, and a node carrying neither would be reported by neither half. Putting the kind on the existing marker means the completeness half already guarantees every operable node has a kind.

**Why this beats hiding the glyph (§2.12).** The hide keeps three assertions green while removing everything they were about. The declaration **narrows** the glyph obligation to the nodes that still offer a glyph and **replaces** it, for the rest, with a different assertion about the affordance that remains. A contract that asserts something about every operable node is what C9 is; a contract that asserts a descendant exists is not.
