## 0. RALPLAN-DR summary

### Principles (5)

- **P47-1 — THE ARTIFACT OWNS ORDER AND ADMISSIBILITY; THE DOM OWNS GEOMETRY ONLY.** The reorder gesture needs an ordered sibling list, and `StructureSection.tsx`'s own docblock forbids deriving one: *"There is deliberately no client-side child walk, no `lastContentChildOid`, and no DOM-derived sibling list anywhere in this file: that classifier is what the addressing ruling deleted, and re-deriving it here would resurrect the classifier↔composer divergence class."* The escape is not an exception to that rule but an application of it: the edit-map already publishes a per-oid `{parentOid, prevOid, nextOid}` chain (`packages/descvi/src/react/overlay/engine/source-resolver.ts#export interface StructureEditInfo {`), computed by the ENGINE's own `packages/descvi/src/extractor/structural-edit.ts#function adjacentOpUnit(` — the same function the server re-derives the write baseline from. **The client walks that published chain for ORDER and reads the DOM only to look up a BOX for an oid the artifact has already admitted.** No verdict is computed client-side, so no second classifier exists to diverge.
- **P47-2 — ONE GESTURE, ONE REQUEST, ONE JOURNAL ENTRY, ONE Cmd+Z.** Phase-45 minted the precedent and stated the reason in the code: `packages/descvi/src/sidecar/commit-write.ts#export type JournalSubject =` carries the `className-batch` arm *"ONE journal entry for an N-member className batch … an undo unit is an ENTRY, so N entries would be N undos however the write was folded."* An n-position drag is the same shape one layer down. Everything in §3.3 follows from refusing to ship a gesture whose undo count is a function of how far the user dragged.
- **P47-3 — A REFUSAL NAMES THE RELATIONSHIP IT IS ABOUT, AND IT IS BILINGUAL.** KI-17 is the standing lesson: a refusal naming the wrong relationship is a shippable defect that shipped and got filed. The reorder refusals are about the PARENT (no flow axis), not about the element, and about the PAIR (unequal indent), not about either member. And they are canvas readouts, so they take the ring family's bilingual channel (`packages/descvi/src/react/overlay/shared/refusal-messages.ts#export function bilingualLine(message: BilingualMessage): string {`), not `StructureSection`'s Korean-only `packages/descvi/src/react/overlay/panel/StructureSection.tsx#const REASON_TEXT: Record<StructuralRefusalReason, string> = {` — phase-46 S46-4 already reversed one Korean-only user-facing string on exactly this ground.
- **P47-4 — THE SHIELD'S ARM TABLE IS A TABLE OVER TARGET CLASSES, AND THIS PHASE ADDS NO ROW TO IT.** See §3.1 and the loud note in §8: the lead's framing that *"phase-47 opens a new arm in that table"* does not survive the design, and building to it would be the third instance of the exact defect the table's own docblock records three times.
- **P47-5 — A GATE THAT HAS NOT BEEN SHOWN RED HAS NOT BEEN BUILT, AND THIS PHASE HAS A CLASS OF CLAIM NO UNIT TEST CAN REACH.** Inherited from the parent's P5 / phase-44's P44-5 / phase-45's P45-5. §5 states a RED-when naming the mutation for every gate. §7 states, separately and without dressing it as a gate, which claims are **owner-decidable only** — an indicator's position and a drag's arming feel are two of them.

### Decision drivers (top 3)

- **D47-1 — THE SUBJECT POPULATION IS SMALL AND SHALLOW, AND THAT PRICES EVERY EXPENSIVE OPTION OUT. (MEASURED, §2.1.)** Over `src/app/**`, of **427** admissible op-unit sibling runs, **192 are singletons** — an element with no reorderable neighbour at all. Only **235** runs have ≥2 members, **62** have ≥3, **21** have ≥4, and the longest run in the corpus is **7**. A 4-position drag is constructible in 21 places on the whole dogfood app. This is the number that decides §3.3: the n-step problem is real and must be *correct*, but it must not be *expensive*.
- **D47-2 — THE NON-FLEX REFUSAL IS PLAUSIBLY THE MAJORITY CASE, NOT AN EDGE. (MEASURED as a PROXY, §2.1.)** Of the 235 multi-member runs, only **83** sit under a parent whose authored base className carries `flex`/`inline-flex`; **152** do not (19 have no oid-bearing parent at all; 54 have a parent whose className the artifact records as `null`). ⚠ **This is a source-token PROXY and an upper bound on the refusal count, because `readLayoutContext` falls back to computed `display` and no static read can evaluate that** — but it settles the order of magnitude. The `canInsertChild` history is the precedent to read: that emitter's own note records a plan justification (*"a rare refusal arrives as a 422"*) that was **false by measurement, the refusal being the MAJORITY case**. The refusal surface is therefore a first-class deliverable of this phase and not a fallback arm (§3.5).
- **D47-3 — THREE SHIPPED CONTRACTS MEET ON THE ORDINARY CANVAS PRESS, AND ALL THREE ARE PINNED BY GATES. (VERIFIED.)** The shield's three-arm target table and its `preventDefault()` (`packages/descvi/src/react/overlay/canvas/use-canvas-selection-shield.ts#function isResizeHandleEvent(e: Event): boolean {` and the ROW P/ROW D docblock beside it — whose own record names **three** occasions the table was got wrong); phase-45's travel guard and its two-condition click consumption (`packages/descvi/src/react/overlay/canvas/use-canvas-selection-shield.ts#        maxTravelRef.current >= POINTER_DRAG_THRESHOLD_PX`); and phase-42's one-shot trailing-click latch. The reorder gesture's target is an **ordinary element**, so it is the first gesture in this repo that must live *inside* the ordinary arm rather than beside it. §3.1 is the whole content of that.

## 3. The design

### 3.1 Arming, ownership and the terminal — the shield's arm table gains NO row (RULED — DR47-1, DR47-2 — C47-1)

**C47-1.** A new headless module `canvas/reorder-drag-machine.ts` (pure: no DOM, no React) and a wiring hook `canvas/use-reorder-drag.ts`. The **only** change to `use-canvas-selection-shield.ts` is ONE call on the existing ordinary arm, immediately after `beginTravelRecording(e)`. The ROW D / ROW P / ordinary table is **unchanged in every arm**, and the shield's docblock gains a paragraph saying so — on phase-45's own precedent for an addition that is orthogonal to the table rather than a row in it.

**(a) The arming predicate — a CONJUNCTION, every term of which is checkable at the press.** The gesture arms as a *candidate* iff ALL of:

1. the press took the **ordinary arm** (so ROW D and ROW P targets are excluded by construction, before this code runs);
2. **no modifier** — `!shiftKey && !metaKey && !ctrlKey && !altKey`. This is what keeps §1's exclusions 4 and 5 true rather than merely declared;
3. the current selection has **at most one member** (§1 exclusion 5);
4. the press resolves, through the shield's own container-scoped resolution, to a `[data-oid]` element inside `#dsh-screen` (this is what keeps the stage background unclaimed — §1 exclusion 2);
5. that oid's published `structure` entry has `canMoveUp || canMoveDown` — i.e. it sits in a run of length ≥ 2 (§2.1: **235 of 427 runs**).

A candidate becomes a **drag** when travel reaches `packages/descvi/src/react/overlay/canvas/pointer-thresholds.ts#export const POINTER_DRAG_THRESHOLD_PX = 4;` — **the shipped symbol, imported, never a copied `4`.** That module's own docblock states the consumption rule this phase must honour: *"a census of `export const` declarations is blind to a machine that hard-codes its own `4`"*, so G47-3 edits the value and asserts the reorder classifier's boundary moves with it.

⚠ **The owner ratified this constant for the resize gesture on measured grounds** (`docs/e3/tracker.md`, phase-42 owner verdicts: 2 of 20 tremor misclassifications accepted, *"revisit only if felt in real use"*). **Whether 4 px is right for a reorder drag is a DIFFERENT felt question on a DIFFERENT gesture and this lane does not settle it** — §7 routes it.

**(b) Capture.** `setPointerCapture` on `#dsh-stage`, mirroring `packages/descvi/src/react/overlay/canvas/use-resize-drag.ts#        handleEl.setPointerCapture(e.pointerId);` in intent but not in host: the resize gesture captures on the handle because the shield's bypass matches on the click's target, and here the shield's suppression is taken by the latch (DR47-2) rather than by a target match. Capture on the stage keeps the move stream and the release attributable when the pointer leaves the frame — the transport half phase-42 measured closed (`docs/e3/tracker.md`, B-Q4 row: the stream and `pointerup` survive 500 px outside the frame; ⚠ that measurement was on the resize gesture, and this plan does **not** re-claim it for a stage-hosted capture — G47-4 re-measures it here).

**(c) The terminal is one idempotent transition over the same trigger set phase-42 enumerated**: `pointerup`, `pointercancel`, `Escape` at `document` capture, selection change, screen change, edit-mode off, unmount. Its final act returns the machine to `idle` — phase-42's recorded lesson that without the return, `terminal` is absorbing and *"the gesture works exactly once per page load"*.

**(d) The trailing click.** On a terminal that followed an ARMED drag, and only then, the wiring calls the shipped `armTrailingClickSuppression()` (`packages/descvi/src/react/overlay/canvas/resize-gesture-guard.ts`). The shield's click arm then takes its existing first branch and returns before resolution — no new condition, no change to phase-45's travel consumption. A candidate that never armed leaves the latch untouched and its click resolves a selection exactly as today, which is what makes a sub-threshold press still a click.

**(e) Furniture during the drag.** The selection ring, the handle layer and the spacing layer are **hidden for the duration of an armed reorder drag** and restored at the terminal. Reason with a mechanism: those three families are anchored to the subject's measured box, the subject does not move during the drag (DR47-3), and the insertion indicator is drawn between siblings — leaving eight resize chips and four spacing strips painted around a stationary element while a blue line moves elsewhere is three families claiming the same explanation. ⚠ **UNVERIFIED that hiding reads better than leaving them; §7 routes it.**

### 3.2 The drop resolution — identity, not ordinal (RULED — DR47-5, DR47-6 — C47-2)

**C47-2.** At arm time the machine builds, once, a **drop table**:

1. **ORDER comes from the artifact.** From the subject's oid, walk `prevOid` to the head and `nextOid` to the tail over the CURRENT edit-map. The result is the ordered list of admissible op-unit siblings, with the subject's index in it. Nothing here reads the DOM.
2. **GEOMETRY comes from the DOM, scoped and joined by oid.** For each oid in that list, find its element **among the descendants of the subject element's own `parentElement`** — never a document- or screen-wide `querySelector`, which a shared oid could satisfy from another instance. Take `getBoundingClientRect()` relative to the ring layer, exactly as the rings and handles do.
 ⚠ **If ANY chain member fails to resolve to exactly one element in that subtree, the gesture refuses outright rather than dropping that member.** A partial table would silently mis-place. This is the `ambiguous-oid` posture applied client-side to a lookup rather than to a verdict.
3. **AXIS.** `deriveParentContext(subjectEl).direction` for `row` / `col`; `unset` means base-flex with no direction token, which is CSS `row`. **REVERSAL is read separately**, once, as `getComputedStyle(parentEl).flexDirection.endsWith("-reverse")` (DR47-6) — a geometry read, never an admissibility one.
4. **HIT-TEST.** The pointer resolves to (sibling `S`, `side ∈ {leading, trailing}`) by which sibling's box contains it (or is nearest, when the pointer is in a gap) and which half along the main axis. For a wrapping parent this is still well-defined, because the answer is about ONE box and not about a projection onto one axis.
5. **VISUAL → SOURCE.** `sourceSide = reversed ? flip(side) : side`. The destination is then *"immediately `sourceSide` of `S` in the chain"*, expressed as the pair `{prevOid, nextOid}` that the destination gap sits between — the same triple shape the origin receipt already uses.
6. **NO-OP DETECTION.** A destination equal to the subject's current position produces no request at all. This is not an optimisation: `packages/descvi/src/extractor/structural-edit.ts#export function moveAdjacent(` with k = 0 has no meaning, and a request that writes nothing still pushes a journal entry and costs a Cmd+Z.

⚠ **What (2) is NOT:** it computes no eligibility. Every oid it looks up was admitted by the engine; the DOM is asked only *"where is this box"*. That is the line P47-1 draws, and it is the line StructureSection's prohibition is actually about.

### 3.3 The write — one request, a destination receipt, one journal entry, one Cmd+Z (RULED — DR47-4 — C47-3)

**C47-3.** `target: 'structure'`, verb `move-up` or `move-down` (chosen by the sign of the source-order displacement), unchanged `expect: {parentOid, prevOid, nextOid}` for the ORIGIN, plus **one new optional field** `expectDestination: {prevOid, nextOid}`.

Server, inside `prepare`, under the write lock:

1. resolve the op-unit and re-derive the live origin baseline; mismatch ⇒ `stale-baseline` (409), unchanged;
2. re-derive the live chain and locate the destination gap named by `expectDestination`; **not found, or not in the same parent ⇒ `stale-baseline` (409)** carrying the live origin baseline exactly as today, so the shipped 409 resync path needs no new client arm;
3. compute `k` = the number of adjacent swaps from origin to destination, and the direction; assert the direction agrees with the wire verb (disagreement is a 400 — the client contradicted itself);
4. apply `moveAdjacent` **k times** to the evolving page source, passing `expect` on the FIRST application only (subsequent steps are re-derivations of a baseline this transaction itself moved);
5. any step's typed refusal — `unequal-indent`, `non-canonical-separator`, `unsupported-sibling`, `no-adjacent-sibling` — aborts `prepare`, so **nothing is written**, and the 422 carries that reason;
6. one journal push, subject unchanged: `{ kind: 'structure', op: 'move-up' | 'move-down', screenId, oid }`. `packages/descvi/src/sidecar/commit-write.ts#export function reselectTargetFor(subject: JournalSubject): string | null {` needs **no new arm**, because no arm was added.

**THE ANSWER TO §4(c)'s QUESTION, STATED PLAINLY: one Cmd+Z after a 4-position drag takes the element back four positions, to exactly where it started.** One request, one entry, one undo — and the entry's stored `before` bytes are the whole file as it stood before the gesture, so the revert is byte-exact rather than four re-derived inverse moves.

**Why `expectDestination` is not a new write class, and the narrower reading is stated so a reviewer can attack the right thing.** The owner's constraint is *"rides v2's existing `move-up`/`move-down` verbs (no new write class)"*. A **write class** in this codebase is a MUTATION KIND — the module's own header names them: *"Where `text-edit.ts` / `classname-edit.ts` / `binding-edit.ts` replace the bytes of a single LITERAL, this module cuts, inserts and reorders whole JSX ELEMENTS. That is a new mutation class."* `expectDestination` adds no mutation kind, no `StructuralOp` member, no journal arm, no refusal reason and no composer; it adds a **receipt**, which is the mechanism `expect` already is. ⚠ **The wider reading — that any wire-shape change violates the ruling — is available and this lane does not have the standing to dismiss it; §8.3 routes it.** Under the wider reading the fallback is to ship k = 1 only, which §2.1 prices exactly: **173 of the 235 multi-member runs have exactly two members, so k can only be 1 there anyway**, and only 62 runs could ever produce k ≥ 2.

**Cost inside the lock (UNVERIFIED, and it is the one number this plan refuses to guess).** `moveAdjacent` re-parses per call, so k steps cost k parses. Phase-45 measured swc at **2.58–2.63 ms/parse** on the largest page in this tree (`docs/e3/tracker.md`, DR45-6), and §2.1 bounds k at **6** (longest run 7). S47-2 re-derives that product on this tree rather than carrying phase-45's number into a different call shape; if it exceeds the budget the fix is a k-step composer over one parse, and that is a *known* fallback rather than a discovered one.

## 9. ADR

**Decision.** Ship drag-to-reorder as a gesture that (i) arms inside the shield's existing ordinary press arm, adding no row to its target table; (ii) resolves its drop by sibling IDENTITY against the edit-map's published `prev`/`next` chain, using the DOM only for boxes; (iii) writes it as ONE structural request carrying a destination receipt, folded server-side into k applications of the shipped `moveAdjacent` inside one `prepare`, yielding one journal entry and one Cmd+Z; (iv) surfaces a blue insertion indicator and a drag readout as non-operable ring-layer readouts on the shipped `styleReadout`; (v) refuses under a parent with no flow axis, in bilingual words naming the parent rather than the element; and (vi) fixes `undo-focus-ownership` by widening the Cmd+Z ownership guard rather than by moving focus.

**Drivers.** D47-1, the measured subject population — 235 reorderable runs, 62 of length ≥ 3, longest 7 — which prices out every design that pays per-step. D47-2, the measured (proxy) finding that the non-flex refusal is plausibly the majority case, which makes the refusal surface a deliverable rather than a fallback. D47-3, the three shipped, gated contracts that meet on the ordinary canvas press, one of which has been broken three recorded times.

**Alternatives considered.** A fourth shield arm (DR47-1a) — rejected because a reorder press must keep every ordinary-arm behaviour, so a fourth row would have to re-implement the third. A second stage listener (DR47-1b) — spec-legal, rejected because it gives one press two owners. N sequential POSTs (DR47-4a) — rejected on undo count, round-trip count and non-atomicity. A `steps: number` (DR47-4b) — rejected because a count is not verifiable against a stale chain and a coordinate is; G47-10 is that argument made executable. A new `move-to` verb (DR47-4c) — rejected as the reading of the owner's constraint most likely to violate it, at the price of five ripples. A geometric ordinal drop (DR47-5a) — rejected as silently wrong on reverse and wrapping parents. A live DOM reorder preview (DR47-3a) — rejected because `#dsh-screen`'s children belong to React. A panel-hosted Korean-only refusal (DR47-7a) — rejected on surface and on `AGENTS.md`'s bilingual rule, with phase-46 S46-4's reversal as precedent. Moving default focus to `#dsh-screen` (DR47-9a) — rejected because it moves focus in a file with a documented focus-steal defect family, and would put a new `[tabindex]` node inside the stage.

**Consequences.**

- The shield's ordinary arm gains a second consumer, and the arm table's docblock gains a paragraph saying it gained no row.
- `POINTER_DRAG_THRESHOLD_PX` acquires a fourth consumer; its own docblock's claim that a declaration census cannot see a hard-coded copy now covers one more machine, and G47-3 is what keeps that honest.
- The trailing-click one-shot acquires a second producer; the residual is bounded by target-disjointness and by drop-on-press, and is recorded rather than closed.
- The wire gains one optional field and **no** new verb, mutation class, journal arm or refusal reason.
- The ring layer gains a fourth and fifth readout and a new z constant above the resize corners; the C46-0 partition is unmoved because both are non-operable by role.
- `.omc/specs/interaction-ontology.md` §3.F-1 rows 1 and 3 and the §3.F preamble change, and **no register gate watches those edits** — only `check-citation-anchors.mjs` protects the new anchor, and a review lane is the rest.
- A gesture can now show an indicator for a destination the server refuses (`unequal-indent`); accepted, surfaced, with a stated re-rate condition.

## 10. Pre-mortem — three ways this phase ships broken

1. **The shield edit is subtly wrong and everything is green.** Six months on, someone finds that ROW D became unreachable again, or that the ordinary arm stopped calling `preventDefault()` on reorderable targets, and that no behavioural row could see it because every behaviour was mediated by something else. **This is not hypothetical: it is what happened, and the file records it.** The countermeasure is G47-1's `defaultPrevented` triple — a *property* read, not a behaviour — and the S47-3 brief's requirement to quote the arm order back before editing.
2. **One Cmd+Z is asserted, and it passes for the wrong reason.** The gate drags a subject one position (k = 1) because that is what the corpus makes easy — §2.1 says 173 of 235 runs can only produce k = 1 — and a k-per-request implementation passes it. The phase ships, and the first 3-position drag in real use costs three undos. **The countermeasure is that G47-8 specifies a run of 5 and a drag of 3, and that S47-0 owes such a run as a fixture if the audit finds none.** A gate whose subject the corpus cannot supply is a gate that will quietly be weakened to fit.
3. **The refusal is right and the words are wrong.** Every reason code is asserted, every test is green, and the shipped Korean sentence tells the user their *element* cannot be reordered when the truth is about its *parent* — so they try a different element instead of adding auto-layout. **This is KI-17, exactly, and phase-46's own landing record notes that the class survived because every structural test asserted the reason CODE and none asserted the WORDS.** The countermeasure is G47-11's second leg, which asserts the words and can only go RED on a substitution.
