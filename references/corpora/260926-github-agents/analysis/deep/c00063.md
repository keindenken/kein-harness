## What it is for and who reads its output

It is the documentation step of the MoAI SPEC lifecycle (plan → run → sync). After an implementation run it writes the `CHANGELOG.md` `[Unreleased]` entry, syncs `README.md`, syncs the framework's docs site in four locales, and flips the SPEC status fields on the sync commit. It has two readers. Humans read the CHANGELOG, README and docs site. The orchestrator and the `sync-auditor` read the machine block it writes into `progress.md` ("`§E.4 Sync-phase Audit-Ready Signal` YAML block") and any blocker report it returns. Most of the file is about lifecycle ownership. Only a small part is about writing.

## Operating procedure in brief

1. "**Source analysis**": scan the source tree, extract endpoints, functions and config, and find usage examples in comments and tests.
2. "**Architecture**": choose the content hierarchy, navigation and page types ("guide / reference / tutorial").
3. "**Content generation**": write pages "with progressive disclosure for beginner-friendly content" and add Mermaid diagrams.
4. "**Validation**": run lint, Mermaid syntax, link and build checks as one parallel Bash batch.
5. Before appending to the CHANGELOG, run three mandatory self-tests (duplicate grep, acceptance-criteria count match, path existence), then make one sync commit that moves all four SPEC artifacts `in-progress → implemented → completed`.
6. If sync shows that a SPEC body needs changing, stop and return a structured blocker report instead of editing it.
