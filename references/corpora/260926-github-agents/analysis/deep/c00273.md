## What it is for and who reads it

It rewrites one episode of a serialized Korean web novel so the episode matches the setting documents, taking as input two reports from sibling agents (revision-analyst and character-sculptor). There are two readers. The episode file is read by Korean web-novel readers, and the goal is stated in reader terms:

> 5. **한국어가 살아야 한다**: 번역체·기계적 반복을 철저히 배제하고, 한국 독자가 읽었을 때 "사람이 쓴 글"로 느끼게 한다.

(Korean must live: remove translationese and mechanical repetition so a Korean reader feels a person wrote it.) The second reader is the orchestrator, which gets a "Rewrite Execution Report" printed after the file is saved.

## Operating procedure in brief

1. Read the two analysis reports and set priorities.
2. Write a scene design sheet per the project's CLAUDE.md.
3. Write the ending (last 500 characters) first, following the plot guide's hook type.
4. Write the opening (first 1,000 characters), dropping straight into the event.
5. Fill the scenes, applying the character and writing-rule checklists.
6. Run a mandatory grep self-audit against numeric caps and replace sentences over the cap.
7. Overwrite `episode/ep{NNN}.md`.
8. Print the report in a fixed multi-table format.

## What it has that the proposed writer lacks (verbatim)

- A ranked source of truth for a genre where "evidence" is not code or data. The setting documents play the role that code plays for project docs:

  > 2. **설정문서가 진실이다**: 오케스트레이터가 지정한 플롯 가이드의 비트가 정본. 에피소드가 다르면 에피소드를 바꾼다.

  (The setting document is the truth: the plot guide's beats are canonical; if the episode differs, change the episode.) This shows point 2 of the proposal generalizes to fiction if "evidence" is defined per doc type, which the proposal leaves to the path rule or brief.
- Preservation constraints handed down by the caller, with absolute priority:

  > 4. **보존 가드레일은 절대적이다**: 오케스트레이터가 전달한 가드레일({GUARD_RAILS} + {REVISE_GUARD_RAILS})을 절대 훼손하지 않는다.

  (Preservation guardrails are absolute: never damage the guardrails the orchestrator passes.) The proposal says nothing about rewriting an existing document: what must survive a rewrite. For README or prompt edits this is the same problem (sections, anchors, or measured wording that must not move).
- An explicit stance on rewrite versus patch:

  > 1. **재작성은 새로 쓰는 것이다**: 기존 문장을 패치하는 것이 아니라, 장면 설계서부터 다시 만든다.

  (Rewriting is writing anew: do not patch sentences, rebuild from the scene design.) The proposal has no position on when to patch and when to regenerate.
- Countable style defects with numeric caps, checked by a tool rather than by the model's judgment:

  > 화당 5회를 넘으면 단조로움. 명사 단독 제시, 다른 동사, 형용사 전환 등으로 교체.

  > echo "=== 있었다 (<=5) ===" && grep -c "있었다" $FILE

  > 상한 초과 시 해당 문장을 교체하고 다시 저장한다.

  (More than 5 per episode is monotonous; replace. If over the cap, replace the sentence and save again.) This is compatible with the proposal's "does not judge the quality of its own output": a grep count is a measurement, not a self-verdict. The proposal could name this as the allowed kind of self-check.
- Consistency across a series of documents, checked mechanically:

  > - **화 간**: 직전 2화에서 사용한 비언어를 grep으로 확인. 3화 연속 금지.

  (Across episodes: grep the previous two episodes for the non-verbal cues used; no cue three episodes in a row.) The proposal treats each document alone.
- A substitution test for dialogue:

  > 3. **교체 불가 검증** — 화자를 바꿔도 자연스러우면 DNA가 부족

  (Irreplaceability check: if the line still reads naturally with a different speaker, the character's voice is missing.) A concrete, checkable test in place of an adjective like "distinct voices".
- A caller-facing report kept out of the deliverable, including a change table:

  > ## 수치 정정
  > | 항목 | 원본 | 정정 |

  (Numeric corrections: item, original, corrected.) This matches point 3's separate output, and the corrections table is close to the proposal's ledger, keyed by change instead of by claim.

## Where it conflicts with the proposal

- Combining unit: it merges two reports ("revision-analyst와 character-sculptor 보고서를 읽고 우선순위 정리.") but never says how to rank them when they disagree. The proposal's unit is a claim with a source and an evidence tier; here the unit is a whole report and the priority rule is left to the model.
- Point 3 (cutting is the default): there is no cutting rule. The report records length ("분량: {N}자 (원본: {N}자)") with no target, and the procedure only adds (scene design, ending, opening, "살 붙이기", fleshing out).
- Self-judgment: the report table asks the agent to fill "{OK/OVER}" verdicts itself, and Step 6 is labelled "자기 검수 (필수)" (mandatory self-review). For the three grep counts this is measurement; for the other checklists ("캐릭터 입체성 체크리스트와 집필 규칙 체크리스트를 적용한다.") it is the model grading itself.
- Point 1: the reader is named at the level of "한국 독자" (Korean reader) only. What the reader does with the episode (keep reading to the next paid episode) is carried by the hook step, not stated.

## What it gets wrong or what looks untested

- The mechanical check undercounts. `grep -c` counts matching lines, not occurrences. Korean prose paragraphs are often one line in markdown, so two "있었다" in one paragraph count once and the cap of 5 is looser than stated. `grep -o ... | wc -l` would count occurrences.
- Only three of the seven prose patterns have a check. Pattern 2 ("동일 어미 연속 4문장 이하", at most 4 consecutive sentences with the same ending), pattern 3 (subject repetition), 5, 6 and 7 have no mechanical test, and the script checks "것이었다 (<=1)", a cap that appears in none of the seven patterns. The cap list and the check list were not kept in sync.
- The original is overwritten before the report is produced ("episode/ep{NNN}.md에 재작성된 본문을 저장한다."), yet the report needs the original's length and scene list. Nothing tells the agent to record those before Step 7.
- Tension between two rules on non-verbal tags: principle 2 asks to vary tags across "5단계 강도" (five intensity levels), while core principle 6 says "비언어 태그를 기계적으로 삽입하지 않는다" (do not insert non-verbal tags mechanically). A tag palette with per-episode quotas pushes toward exactly the insertion it forbids.
- Heavy dependence on files outside the prompt: CLAUDE.md's writing process, `${CLAUDE_PLUGIN_ROOT}/skills/rewrite/references/rewrite-quality-criteria.md`, alive-tracker.md, the dialogue-DNA document, and template placeholders ({GUARD_RAILS}). The caps (5, 3, 1, "3회 연속") look drawn from experience with translationese, but the file gives no measurement behind them.

## Verdict

Not a base for the general writer: it is a single-genre, single-language rewrite executor whose value sits in genre content. It is a strong exemplar of the mechanism the proposal wants outside the role: a path-scoped rule for `episode/**` could carry the caps, the grep check and the series-consistency check, while the general role keeps "setting documents are the truth" as its point 2 and the execution report as its separate output. Two techniques are worth lifting into the general role's wording: numeric, tool-checked caps as the permitted form of self-check, and preservation guardrails passed by the caller for any rewrite. Evidence weight is low: one voice, copied once.
