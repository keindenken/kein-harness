## What it is for and who reads it

It writes persuasive copy for one product space, agentic advertising: website and landing pages for agenticadvertising.org, email sequences, positioning, and also text that models read (MCP tool descriptions, A2A agent cards, GPT store listings, Claude skill descriptions, agent persona voice). It states both readers:

> You know the audience: media buyers, ad ops teams, marketing technologists, agency strategists, and the AI agents that work alongside them.

and switches register by reader:

> These are surfaces where an AI model reads your words and decides what to do. Clarity and precision matter more than persuasion.

## Operating procedure in brief

There is no ordered procedure. The file is a catalogue: per-surface rules ("What You Write"), six writing principles, three frameworks (AIDA, PAS, Before/After/Bridge), word lists, an audience calibration table, and a per-request deliverable menu ("What You Deliver") for website copy, tool descriptions and personas.

## What it has that the proposed writer lacks (verbatim)

- A sentence-by-sentence contract for tool descriptions, one of the prompt-instructions doc types the proposal names but does not specify:

  > - First sentence: what it does (action + object)
  > - Second sentence: what it returns (shape of the response)
  > - Third sentence (if needed): when NOT to use it (disambiguation)
  > - No marketing language - agents don't respond to "powerful" or "comprehensive"
  > - Under 100 words total

  with a paired example:

  > DO: "Search for campaigns by name, status, or date range. Returns

  This is the most transferable part of the file for a prompt/tool-description path rule.
- A reader-to-register table, a concrete form of point 1:

  > | Developers | Terse, show-don't-tell | Very high | Docs quality, API design, examples |

  The proposal says to start from the reader; this shows how a reader maps to tone and depth.
- A quantified cutting target, stronger than the proposal's "cutting is the default":

  > First draft is for getting ideas down. Second draft is for cutting 40% of the words. If a sentence doesn't advance the argument, delete it. If an adjective doesn't add information, delete it.
- Options for the caller instead of one answer, where the choice is a judgment call:

  > 1. **Headline + subhead** - 2-3 options with different angles
- A before/after beside an edit of existing text, which is close to the proposal's caller-facing output:

  > 4. **Before/after comparison** - Show the improvement over current
- A consistency test for voice work:

  > - Consistency tests: would this persona say X? What about in situation Y?

## Where it conflicts with the proposal

- Point 2 (traceable to evidence): there is no evidence rule, and the examples model unsourced specifics. The principle is credibility, not truth:

  > Specific claims are more credible and more memorable.

  and its "good" example is a number with no source:

  > Good: "Launch a campaign in one sentence instead of 47 form fields"

  An agent following this learns to produce specific-sounding numbers. For marketing copy, where claims about a product reach customers, this is the doc type that most needs point 2, and the file has none. "Social proof sections that show real results" likewise has no rule about where results come from.
- Doc-type differences live inside the role, the opposite of the proposal's design: seven surfaces each get their own rule block, all in one file. The file is general-purpose across surfaces but locked to one domain.
- Self-judgment: the website deliverable includes a self-assessment, "4. **Tone check** - Confirms alignment with brand voice", which is the model grading its own output in the deliverable to the caller.

## What it gets wrong or what looks untested

- Its own cutting example breaks two of its other rules. The "After" line is:

  > After:  "Manage campaigns across every channel with AI that actually works."

  "AI that actually works" is the vague superlative its word list bans (`- "AI-powered" without saying what the AI actually does` is listed under Words to Avoid) and is hyperbole under principle 6. Examples in a prompt are copied more readily than rules, so this one teaches the opposite of the rule next to it.
- PAS tells the writer to "**Agitate**: Show why it's getting worse or what they're missing", which pulls against "No Hyperbole" and "Earn trust with specificity and honesty." No rule reconciles them.
- It addresses the model with a claim about a file it may not load: `Your CLAUDE.md says "no hyperbole"`. The rule is restated in place, so this is harmless, but the pointer adds nothing.
- The Claude Skills block is thin compared with the tool-description block: "- Instructions: concise, specific, no conflict with base behavior". It says nothing about trigger wording, length, or what a skill description is for beyond a question.
- The claims about agent readers (`agents don't respond to "powerful" or "comprehensive"`, "Under 100 words total") are plausible but asserted; the file cites no test of tool-selection accuracy.

## Verdict

Not a base for the general writer: it is a domain-specific persuasion catalogue with no evidence rule, and it puts every surface's rules in the role. Two parts are worth lifting. The Agent-Facing Copy block, especially the three-sentence tool-description contract with its DO/DON'T pair, is a good seed for a path-scoped rule on tool and skill descriptions (the prompt-instructions type). The audience calibration table and the 40% cut target are good wording for the general role's points 1 and 3. For marketing copy it would need a claim-source rule before use, and its "After" example should be replaced. Evidence weight: one organization, one voice, although it is the highest-starred file of the five.
